# Chapitre 6 — Scripting bash


## 1. Quand écrire un script bash ?

Bash est excellent pour **enchaîner des commandes** : automatiser une installation, orchestrer une sauvegarde, lancer un déploiement, vérifier l'état d'un serveur. Tout ce que vous tapez régulièrement à la main mérite d'être scripté.

Bash devient en revanche pénible dès qu'il faut manipuler des structures de données complexes, faire des calculs sérieux, parser du JSON ou gérer beaucoup de logique. Une règle empirique courante : **au-delà d'une centaine de lignes, ou dès que le script contient beaucoup de logique métier, passez à Python** (ou au langage de votre équipe).

---

## 2. Premier script

```bash
#!/usr/bin/env bash
# bonjour.sh — un premier script
echo "Bonjour, $USER ! Nous sommes le $(date +%d/%m/%Y)."
```

La première ligne, le **shebang**, indique au système quel interpréteur utiliser. `#!/usr/bin/env bash` cherche `bash` dans le `PATH`, ce qui est plus portable que `#!/bin/bash`. Les lignes commençant par `#` sont des commentaires.

```bash
chmod +x bonjour.sh
./bonjour.sh
```

### Les différentes façons de lancer un script

| Commande | Effet |
|---|---|
| `./script.sh` | Exécute le script dans un **nouveau processus**, avec l'interpréteur du shebang. Nécessite le droit `x` |
| `bash script.sh` | Exécute le script avec bash, sans tenir compte du shebang ni du droit `x` |
| `source script.sh` ou `. script.sh` | Exécute le script **dans le shell courant**. Les variables et les `cd` qu'il contient affectent votre shell |

`source` sert à charger des variables ou des fonctions (c'est ce qu'on fait avec `source ~/.bashrc`). Un script normal s'exécute avec `./`.

> ⚠️ Un script écrit dans un éditeur Windows peut contenir des fins de ligne `\r\n`, qui provoquent des erreurs comme `/usr/bin/env: 'bash\r': No such file or directory`. Corrigez avec `sed -i 's/\r$//' script.sh` et configurez votre éditeur en fins de ligne « LF ».

## 3. Variables

### Définir et utiliser

```bash
nom="Alice"
age=32
echo "Bonjour $nom, tu as $age ans"
echo "Fichier : ${nom}_rapport.txt"     # accolades pour délimiter le nom
```

> ⚠️ **Pas d'espace autour du `=`.** `nom = "Alice"` est interprété comme la commande `nom` avec les arguments `=` et `"Alice"`, d'où l'erreur `nom: command not found`.

### Les guillemets : la règle d'or

| Syntaxe | Comportement |
|---|---|
| `"texte $var"` | Guillemets doubles : les variables et `$( )` sont remplacées, les espaces sont préservés |
| `'texte $var'` | Apostrophes : **tout est littéral**, rien n'est remplacé |
| `$var` sans guillemets | La valeur est découpée sur les espaces et les jokers sont interprétés |

```bash
fichier="mon rapport.txt"
touch $fichier         # ❌ crée deux fichiers : « mon » et « rapport.txt »
touch "$fichier"       # ✅ crée « mon rapport.txt »
rm $fichier            # ❌ tente de supprimer « mon » et « rapport.txt »
```

> 💡 **Mettez toujours vos variables entre guillemets doubles : `"$var"`.** C'est la source d'erreur numéro un en bash, et parfois une erreur grave : un `rm -rf $dossier/` avec une variable vide devient `rm -rf /`.

### Substitution de commande et calcul

```bash
aujourdhui=$(date +%F)                 # résultat d'une commande
nb_fichiers=$(ls | wc -l)
total=$(( 3 * 4 + 2 ))                 # calcul entier
compteur=$(( compteur + 1 ))
```

L'ancienne syntaxe avec des accents graves `` `date` `` fonctionne encore, mais `$( )` est plus lisible et s'imbrique facilement.

Bash ne calcule que sur des **entiers**. Pour des nombres décimaux, utilisez `bc` ou `awk` : `echo "10 / 3" | bc -l`.

### Manipuler les valeurs

Bash sait transformer une variable sans appeler de programme externe :

| Syntaxe | Résultat | Exemple avec `f="photo.vacances.jpeg"` |
|---|---|---|
| `${#f}` | Longueur | `18` |
| `${f%.jpeg}` | Retire le suffixe le plus court | `photo.vacances` |
| `${f%%.*}` | Retire le suffixe le plus long | `photo` |
| `${f#*.}` | Retire le préfixe le plus court | `vacances.jpeg` |
| `${f##*.}` | Retire le préfixe le plus long (donne l'extension) | `jpeg` |
| `${f/jpeg/jpg}` | Remplace la première occurrence | `photo.vacances.jpg` |
| `${f^^}` | Majuscules | `PHOTO.VACANCES.JPEG` |

### Valeurs par défaut et obligatoires

```bash
port=${PORT:-8080}                     # PORT si défini et non vide, sinon 8080
dest=${1:-/tmp}                        # 1er argument, sinon /tmp
: "${API_KEY:?variable API_KEY obligatoire}"   # arrête le script si API_KEY est vide
```

### Portée et environnement

```bash
readonly VERSION="1.2.0"               # constante
export DATABASE_URL="postgres://..."   # transmise aux programmes lancés par le script
```

Une variable non exportée n'existe que dans le script. Une variable exportée est transmise aux processus enfants, mais **jamais** au processus parent : un script ne peut pas modifier les variables du shell qui l'a lancé (sauf avec `source`).

## 4. Arguments et variables spéciales

```bash
./deploy.sh production v1.4 --force
```

| Variable | Valeur |
|---|---|
| `$0` | Nom du script (`./deploy.sh`) |
| `$1`, `$2`, ... | Arguments (`production`, `v1.4`, ...) ; au-delà de 9 : `${10}` |
| `$#` | Nombre d'arguments (`3`) |
| `"$@"` | Tous les arguments, chacun préservé séparément |
| `$?` | Code de retour de la dernière commande |
| `$$` | PID du script |
| `$!` | PID de la dernière commande lancée en arrière-plan |

```bash
#!/usr/bin/env bash
echo "Script : $0"
echo "Nombre d'arguments : $#"
for arg in "$@"; do
  echo "- $arg"
done
```

> 💡 Utilisez toujours `"$@"` (avec les guillemets) pour transmettre les arguments : il préserve les arguments contenant des espaces. `$*` et `$@` sans guillemets les découpent.

`shift` décale les arguments : `$2` devient `$1`, etc. Pratique pour traiter les arguments un par un.

### Lire une saisie

```bash
read -p "Nom du serveur : " serveur
read -s -p "Mot de passe : " mdp; echo     # -s : saisie masquée
read -p "Confirmer ? [o/N] " rep
```

## 5. Codes de retour

Chaque commande se termine avec un **code de retour** (exit status) : **0 signifie succès**, toute autre valeur (1 à 255) signifie échec. C'est l'inverse de la plupart des langages, où 0 est « faux ».

```bash
ls /etc > /dev/null
echo $?            # 0
ls /nexistepas 2> /dev/null
echo $?            # 2
grep -q root /etc/passwd
echo $?            # 0 si trouvé, 1 sinon
```

Un script renvoie le code de sa dernière commande, ou celui indiqué par `exit` :

```bash
exit 0             # succès
exit 1             # échec
```

Renvoyer un code correct est essentiel : c'est ce que regardent `cron`, systemd, les pipelines de CI et les autres scripts pour savoir si tout s'est bien passé.

### Enchaîner selon le résultat

```bash
mkdir /srv/app && cd /srv/app          # cd seulement si mkdir a réussi
cd /srv/app || exit 1                  # quitter si cd échoue
apt update && apt upgrade -y
ping -c1 serveur > /dev/null || echo "serveur injoignable"
```

`&&` exécute la suite si la commande précédente a **réussi** ; `||` si elle a **échoué**.

## 6. Conditions

### `if`

```bash
if commande; then
  ...
elif autre_commande; then
  ...
else
  ...
fi
```

`if` teste le **code de retour** d'une commande. N'importe quelle commande fait l'affaire :

```bash
if grep -q "^alice:" /etc/passwd; then
  echo "alice existe"
fi

if ! ping -c1 -W2 db > /dev/null 2>&1; then
  echo "La base de données ne répond pas" >&2
  exit 1
fi
```

### Les tests avec `[[ ]]`

Pour comparer des valeurs ou tester des fichiers, on utilise la commande de test `[[ ]]`. Les espaces à l'intérieur des crochets sont **obligatoires**.

```bash
if [[ "$env" == "production" ]]; then
  echo "Attention, production !"
fi
```

Tests sur les chaînes :

| Test | Vrai si |
|---|---|
| `[[ -z "$a" ]]` | La chaîne est vide |
| `[[ -n "$a" ]]` | La chaîne n'est pas vide |
| `[[ "$a" == "$b" ]]` | Égales |
| `[[ "$a" != "$b" ]]` | Différentes |
| `[[ "$a" == *.log ]]` | Correspond au motif (joker) |
| `[[ "$a" =~ ^[0-9]+$ ]]` | Correspond à l'expression régulière |

Tests sur les nombres :

| Test | Signification |
|---|---|
| `-eq` / `-ne` | Égal / différent |
| `-lt` / `-le` | Inférieur / inférieur ou égal |
| `-gt` / `-ge` | Supérieur / supérieur ou égal |

```bash
if [[ $# -lt 2 ]]; then echo "Il faut 2 arguments" >&2; exit 1; fi
if (( usage > 90 )); then echo "Disque presque plein"; fi    # syntaxe arithmétique, plus lisible
```

Tests sur les fichiers :

| Test | Vrai si |
|---|---|
| `-e` | Le chemin existe |
| `-f` | C'est un fichier ordinaire |
| `-d` | C'est un dossier |
| `-L` | C'est un lien symbolique |
| `-r` / `-w` / `-x` | Lisible / modifiable / exécutable par l'utilisateur courant |
| `-s` | Le fichier existe et n'est pas vide |
| `f1 -nt f2` | f1 est plus récent que f2 |

Combinaisons : `&&` (et), `||` (ou), `!` (non) à l'intérieur de `[[ ]]`.

```bash
if [[ -f "$config" && -r "$config" ]]; then
  source "$config"
fi
```

> 💡 **`[[ ]]` ou `[ ]` ?** `[ ]` est la commande historique `test`, disponible dans tous les shells POSIX. `[[ ]]` est propre à bash, mais plus sûre (pas de découpage des variables, support des motifs et des expressions régulières). Dans un script bash, utilisez `[[ ]]`.

### `case`

Plus lisible qu'une série de `elif` quand on compare une valeur à plusieurs possibilités :

```bash
case "$1" in
  start)
    echo "Démarrage..." ;;
  stop)
    echo "Arrêt..." ;;
  restart|reload)
    echo "Redémarrage..." ;;
  *.conf)
    echo "Fichier de configuration : $1" ;;
  *)
    echo "Usage : $0 {start|stop|restart}" >&2
    exit 1 ;;
esac
```

## 7. Boucles

### `for` sur une liste

```bash
for serveur in web db bastion; do
  echo "Ping de $serveur"
  ping -c1 "$serveur"
done

for f in /var/log/*.log; do
  echo "$f : $(wc -l < "$f") lignes"
done

for i in {1..10}; do echo "$i"; done
for (( i = 0; i < 10; i++ )); do echo "$i"; done
```

> ⚠️ **Ne parcourez jamais la sortie de `ls`** (`for f in $(ls)`) : les noms contenant des espaces sont découpés. Utilisez directement un joker : `for f in *`.

> ⚠️ Si aucun fichier ne correspond au joker, bash laisse le motif tel quel : la boucle s'exécute une fois avec la valeur littérale `/var/log/*.log`. Protégez-vous avec `shopt -s nullglob` en début de script, ou avec un test `[[ -e "$f" ]] || continue`.

### `while`

```bash
compteur=0
while (( compteur < 5 )); do
  echo "Tour $compteur"
  compteur=$(( compteur + 1 ))
done

# Attendre qu'un service réponde
until curl -sf http://localhost:8080/health > /dev/null; do
  echo "En attente du service..."
  sleep 2
done
```

### Lire un fichier ligne par ligne

```bash
while IFS= read -r ligne; do
  echo "Ligne : $ligne"
done < fichier.txt

# Avec un séparateur : lire un fichier CSV
while IFS=, read -r login nom groupe; do
  echo "$login appartient à $groupe"
done < utilisateurs.csv
```

`IFS=` préserve les espaces en début et fin de ligne, et `-r` empêche l'interprétation des antislashs. Retenez cette formule telle quelle.

> ⚠️ `cat fichier | while read ...` fonctionne, mais la boucle s'exécute alors dans un sous-shell : les variables modifiées dans la boucle sont perdues à la sortie. Préférez la redirection `done < fichier`.

`break` sort de la boucle, `continue` passe directement au tour suivant.

## 8. Fonctions

```bash
log() {
  echo "$(date '+%F %T') $*"
}

sauvegarder() {
  local source=$1
  local destination=$2
  if [[ ! -d "$source" ]]; then
    log "Source introuvable : $source" >&2
    return 1
  fi
  cp -a "$source" "$destination"
}

log "Début"
sauvegarder /etc /tmp/etc-backup || log "La sauvegarde a échoué"
```

Une fonction reçoit ses arguments dans `$1`, `$2`, `"$@"`, exactement comme un script. Déclarez ses variables avec **`local`** : sans ce mot-clé, elles sont globales et peuvent écraser des variables du reste du script.

Une fonction a deux façons de « renvoyer » quelque chose, à ne pas confondre :

- `return N` renvoie un **code de retour** (succès ou échec), utilisable avec `if` ou `&&` ;
- ce qu'elle **affiche** sur stdout peut être récupéré avec `$( )`.

```bash
usage_disque() {
  df --output=pcent "$1" | tail -1 | tr -dc '0-9'
}

pct=$(usage_disque /)
echo "La racine est utilisée à $pct %"
```

## 10. Écrire des scripts robustes

### Le mode strict

Par défaut, bash est très permissif : une commande qui échoue n'arrête pas le script, et une variable mal orthographiée vaut simplement une chaîne vide. Les scripts de production commencent donc presque tous par :

```bash
set -euo pipefail
```

| Option | Effet |
|---|---|
| `-e` | Arrête le script dès qu'une commande échoue |
| `-u` | Arrête le script si on utilise une variable non définie |
| `-o pipefail` | Un pipe échoue si **n'importe laquelle** de ses commandes échoue (et pas seulement la dernière) |

Pourquoi c'est important :

```bash
cd /srv/app/releases/ancienne
rm -rf *                   # si le cd a échoué, on vide le dossier courant !
```

Avec `set -e`, le script s'arrête sur l'échec du `cd`, et le `rm` n'est jamais exécuté.

> ⚠️ `set -e` a quelques subtilités. Il n'arrête pas le script quand la commande qui échoue fait partie d'un `if`, d'un `while` ou d'une chaîne `&&` / `||` (c'est voulu). Et `(( compteur++ ))` renvoie un échec quand `compteur` vaut 0, ce qui arrête le script : préférez `compteur=$(( compteur + 1 ))`. Si une commande a le droit d'échouer, dites-le explicitement : `grep motif fichier || true`.

### Les messages d'erreur sur stderr

Les messages de diagnostic et d'erreur vont sur la sortie d'erreur, pour ne pas polluer la sortie standard qui peut être utilisée par un autre programme :

```bash
echo "Erreur : fichier introuvable" >&2

die() {
  echo "ERREUR : $*" >&2
  exit 1
}
[[ -f "$config" ]] || die "configuration $config introuvable"
```

### Nettoyer avec `trap`

`trap` exécute une commande quand le script reçoit un signal ou se termine. Avec `EXIT`, le nettoyage a lieu **dans tous les cas** : fin normale, erreur arrêtée par `set -e`, `Ctrl+C`...

```bash
tmpdir=$(mktemp -d)
trap 'rm -rf "$tmpdir"' EXIT

# ... le script travaille dans $tmpdir ...
```

`mktemp` crée un fichier (ou un dossier avec `-d`) temporaire au nom unique et imprévisible, ce qui évite les collisions entre deux exécutions simultanées.

### Les options avec `getopts`

```bash
verbose=0
sortie="rapport.txt"

while getopts ":vo:h" opt; do
  case $opt in
    v) verbose=1 ;;
    o) sortie=$OPTARG ;;
    h) usage ;;
    :) die "l'option -$OPTARG attend une valeur" ;;
    \?) die "option inconnue : -$OPTARG" ;;
  esac
done
shift $(( OPTIND - 1 ))    # les arguments restants sont dans $1, $2...
```

Dans la chaîne `":vo:h"`, une lettre suivie de `:` attend une valeur. Le `:` initial permet de gérer soi-même les erreurs.

### Journaliser

```bash
log() {
  echo "$(date '+%F %T') [$(basename "$0")] $*" >&2
}

logger -t monscript "Sauvegarde terminée"   # envoie le message dans les logs du système
journalctl -t monscript                      # le retrouver
```

## 11. Déboguer

```bash
bash -x script.sh          # affiche chaque commande avant de l'exécuter
bash -n script.sh          # vérifie la syntaxe sans exécuter
```

Dans le script, on peut activer et désactiver la trace autour d'une zone précise :

```bash
set -x
# ... zone à déboguer ...
set +x
```

Pour une trace plus lisible, avec le numéro de ligne :

```bash
export PS4='+ ${BASH_SOURCE}:${LINENO}: '
bash -x script.sh
```

### `shellcheck`

`shellcheck` est un analyseur statique qui détecte la plupart des erreurs classiques : variables sans guillemets, `cd` non vérifié, parcours de `ls`, syntaxe incorrecte. **Utilisez-le systématiquement**, et intégrez-le à votre éditeur ou à votre CI.

```bash
sudo apt install shellcheck
shellcheck script.sh
```


Chaque avertissement a un code (`SC2086`) documenté en détail sur le wiki du projet.

## 12. Planifier avec `cron`

`cron` exécute des commandes à intervalles réguliers. Chaque utilisateur a sa propre table de tâches, la *crontab*.

```bash
crontab -l         # afficher sa crontab
crontab -e         # l'éditer
```

> 💡 Dans WSL, `cron` n'est actif que si systemd est activé (chapitre 1). Vérifiez avec `systemctl status cron`, et au besoin `sudo systemctl enable --now cron`.

### La syntaxe

```
┌──────── minute (0-59)
│ ┌────── heure (0-23)
│ │ ┌──── jour du mois (1-31)
│ │ │ ┌── mois (1-12)
│ │ │ │ ┌ jour de la semaine (0-7, 0 et 7 = dimanche)
│ │ │ │ │
* * * * * commande
```

| Ligne | Signification |
|---|---|
| `*/5 * * * * cmd` | Toutes les 5 minutes |
| `0 * * * * cmd` | Toutes les heures, à la minute 0 |
| `30 2 * * * cmd` | Tous les jours à 2h30 |
| `0 9 * * 1-5 cmd` | Du lundi au vendredi à 9h |
| `0 0 1 * * cmd` | Le 1er de chaque mois à minuit |
| `@reboot cmd` | Au démarrage de la machine |
| `@daily cmd` | Une fois par jour (équivaut à `0 0 * * *`) |

### Les pièges de cron

Un script qui marche parfaitement à la main et échoue sous cron est un classique. Les causes sont presque toujours les mêmes.

**L'environnement est minimal.** Le `PATH` de cron se limite généralement à `/usr/bin:/bin`, et votre `~/.bashrc` n'est pas lu. Utilisez des chemins absolus, ou définissez le `PATH` en tête de crontab.

**Le dossier courant est le home.** Le script ne démarre pas dans son propre dossier : utilisez des chemins absolus.

**La sortie disparaît.** Sans redirection, la sortie est envoyée par mail local (souvent inexistant). Redirigez-la toujours vers un log.

**Le caractère `%` a un sens spécial** dans une crontab (il signifie « nouvelle ligne ») et doit être échappé : `\%`.

Une ligne de crontab bien écrite :

```
PATH=/usr/local/bin:/usr/bin:/bin
30 2 * * * /home/student/bin/backup.sh /home/student/projet >> /home/student/logs/backup.log 2>&1
```

Pour vérifier que cron a bien lancé la tâche :

```bash
journalctl -u cron --since "10 min ago"
```

> 💡 Le site crontab.guru traduit une expression cron en langage clair : pratique pour vérifier une planification avant de la déployer. Au chapitre 8, nous verrons les **timers systemd**, une alternative moderne à cron avec de meilleurs logs.

## 13. Récapitulatif : le squelette d'un bon script

```bash
#!/usr/bin/env bash
# nom-du-script.sh — ce que fait le script, en une ligne
set -euo pipefail

readonly SCRIPT_NAME=$(basename "$0")

usage() {
  echo "Usage : $SCRIPT_NAME [-v] argument" >&2
  exit 1
}

log() { echo "$(date '+%F %T') [$SCRIPT_NAME] $*" >&2; }
die() { log "ERREUR : $*"; exit 1; }

cleanup() {
  # suppression des fichiers temporaires, etc.
  :
}
trap cleanup EXIT

main() {
  [[ $# -ge 1 ]] || usage
  log "Début"
  # ...
  log "Fin"
}

main "$@"
```

Et les réflexes à avoir : `set -euo pipefail`, des guillemets autour de chaque variable, `local` dans les fonctions, les erreurs sur stderr, des codes de retour corrects, un `trap` pour le nettoyage, et un passage par `shellcheck`.

### Exercice 6.2 — Conditions sur les fichiers (niveau de base)

Écrivez un script `quoi.sh` qui prend un chemin en argument et indique s'il s'agit d'un fichier, d'un dossier ou d'un lien symbolique, ou s'il n'existe pas. Pour un fichier, affichez sa taille et précisez s'il est vide et s'il est exécutable. Pour un dossier, affichez le nombre d'éléments qu'il contient.

<details>
<summary>Solution</summary>

```bash
#!/usr/bin/env bash
set -euo pipefail

[[ $# -eq 1 ]] || { echo "Usage : $0 chemin" >&2; exit 1; }
chemin=$1

if [[ -L "$chemin" ]]; then
  echo "$chemin est un lien vers $(readlink -f "$chemin")"
elif [[ -f "$chemin" ]]; then
  echo "$chemin est un fichier de $(stat -c %s "$chemin") octets"
  [[ -s "$chemin" ]] || echo "  il est vide"
  [[ -x "$chemin" ]] && echo "  il est exécutable"
elif [[ -d "$chemin" ]]; then
  echo "$chemin est un dossier contenant $(ls -A "$chemin" | wc -l) élément(s)"
else
  echo "$chemin n'existe pas" >&2
  exit 1
fi
```

Le test du lien vient en premier, car `-f` et `-d` suivent les liens : un lien vers un fichier est aussi considéré comme un fichier.

Attention au piège : `[[ -x "$chemin" ]] && echo ...` renvoie un échec si le fichier n'est pas exécutable. Placé en **dernière** ligne d'un bloc, cela ne pose pas de problème avec `set -e` (le cas des listes `&&` est exempté), mais le script se terminerait avec le code 1 si c'était sa dernière commande. Un `if` explicite est plus sûr.

</details>

### Exercice 6.3 — Renommer en masse (niveau de base)

Préparez un dossier de test :

```bash

```

Écrivez un script qui renomme tous les fichiers `.jpeg` et `.JPEG` du dossier passé en argument en `.jpg`, en affichant chaque renommage. Le script ne doit rien faire si aucun fichier ne correspond, et ne doit jamais écraser un fichier existant.

<details>
<summary>Solution</summary>

```bash
#!/usr/bin/env bash
set -euo pipefail
shopt -s nullglob

dossier=${1:?Usage : $0 dossier}
compteur=0

for f in "$dossier"/*.jpeg "$dossier"/*.JPEG; do
  nouveau="${f%.*}.jpg"
  if [[ -e "$nouveau" ]]; then
    echo "Ignoré, $nouveau existe déjà" >&2
    continue
  fi
  mv -- "$f" "$nouveau"
  echo "$(basename "$f") → $(basename "$nouveau")"
  compteur=$(( compteur + 1 ))
done

echo "$compteur fichier(s) renommé(s)."
```

Le `--` indique à `mv` que ce qui suit n'est pas une option, ce qui protège contre un fichier dont le nom commencerait par un tiret.

### Exercice 6.4 — Créer des comptes depuis un fichier CSV (niveau intermédiaire)

Dans le conteneur `web` du lab (`docker compose exec web bash`), créez le fichier `/root/utilisateurs.csv` :

```
login,nom,groupe
alice,Alice Martin,devs
bob,Bob Dupont,devs
charlie,Charlie Durand,ops
diane,Diane Leroy,ops
```

Écrivez un script qui lit ce fichier et, pour chaque ligne (en ignorant l'en-tête) :

- crée le groupe s'il n'existe pas encore ;
- crée l'utilisateur avec son nom complet en description, un home et bash, s'il n'existe pas encore ;
- l'ajoute à son groupe.

Le script doit pouvoir être relancé sans erreur (on dit qu'il est **idempotent**) et afficher un résumé à la fin.

<details>
<summary>Solution</summary>

```bash
#!/usr/bin/env bash
set -euo pipefail

fichier=${1:?Usage : $0 fichier.csv}
[[ -r "$fichier" ]] || { echo "Impossible de lire $fichier" >&2; exit 1; }
[[ $EUID -eq 0 ]] || { echo "Ce script doit être lancé en root" >&2; exit 1; }

crees=0
existants=0

while IFS=, read -r login nom groupe; do
  [[ "$login" == "login" || -z "$login" ]] && continue

  if ! getent group "$groupe" > /dev/null; then
    groupadd "$groupe"
    echo "Groupe créé : $groupe"
  fi

  if id "$login" > /dev/null 2>&1; then
    echo "Utilisateur déjà présent : $login"
    existants=$(( existants + 1 ))
  else
    useradd -m -s /bin/bash -c "$nom" "$login"
    echo "Utilisateur créé : $login ($nom)"
    crees=$(( crees + 1 ))
  fi

  usermod -aG "$groupe" "$login"
done < "$fichier"

echo "Terminé : $crees créé(s), $existants déjà existant(s)."
```

```bash
id alice; getent group ops
```

`$EUID` contient l'UID effectif de l'utilisateur qui lance le script : 0 pour root.

### Exercice 6.5 — Surveiller les disques (niveau intermédiaire)

Écrivez un script `disques.sh` qui vérifie le taux d'occupation de chaque point de montage passé en argument (par défaut `/`), et affiche une alerte pour ceux qui dépassent un seuil fixé par l'option `-s` (par défaut 80 %). Le script doit se terminer avec le code 1 si au moins une alerte a été levée, pour pouvoir être utilisé par un outil de supervision. Utilisez une fonction pour la vérification.

<details>
<summary>Solution</summary>

```bash
#!/usr/bin/env bash
set -euo pipefail

seuil=80

verifier() {
  local point=$1
  local usage
  usage=$(df --output=pcent "$point" | tail -1 | tr -dc '0-9')
  if (( usage >= seuil )); then
    echo "ALERTE : $point est utilisé à $usage % (seuil $seuil %)" >&2
    return 1
  fi
  echo "OK : $point est utilisé à $usage %"
}

while getopts ":s:" opt; do
  case $opt in
    s) seuil=$OPTARG ;;
    *) echo "Usage : $0 [-s seuil] [point_de_montage...]" >&2; exit 2 ;;
  esac
done
shift $(( OPTIND - 1 ))
[[ $# -gt 0 ]] || set -- /

alerte=0
for p in "$@"; do
  verifier "$p" || alerte=1
done
exit "$alerte"
```

```bash
./disques.sh
./disques.sh -s 1 / /tmp; echo "Code : $?"     # seuil bas pour provoquer une alerte
```

`set -- /` remplace les arguments du script par `/`. La déclaration `local usage` est séparée de son affectation : `local usage=$(...)` masquerait le code de retour de la commande.

</details>

### Exercice 6.6 — Le script de sauvegarde (projet du chapitre)

Écrivez un script `backup.sh` qui sauvegarde un dossier dans une archive `.tar.gz`. Le cahier des charges :

- usage : `backup.sh [-d destination] [-k nombre] dossier_source` ;
- la destination par défaut est `~/backups`, créée si nécessaire ;
- l'archive porte le nom du dossier et un horodatage : `projet_20260915-143000.tar.gz` ;
- le script ne conserve que les `k` sauvegardes les plus récentes de ce dossier (5 par défaut) ;
- chaque étape est journalisée avec la date ;
- une archive incomplète (si le script est interrompu ou échoue) ne doit jamais rester dans la destination ;
- les erreurs (source inexistante, option invalide) sont signalées clairement, avec un code de retour non nul ;
- le script passe `shellcheck` sans avertissement.

Testez-le en le lançant plusieurs fois de suite avec `-k 3` sur un dossier de votre choix.

<details>
<summary>Solution</summary>

```bash
#!/usr/bin/env bash
# backup.sh — sauvegarde d'un dossier en .tar.gz avec rotation
set -euo pipefail

SCRIPT_NAME=$(basename "$0")
readonly SCRIPT_NAME
DEST="$HOME/backups"
KEEP=5

usage() {
  cat >&2 << EOF
Usage : $SCRIPT_NAME [-d destination] [-k nombre] dossier_source
  -d  dossier de destination (défaut : $DEST)
  -k  nombre de sauvegardes à conserver (défaut : $KEEP)
EOF
  exit 1
}

log() { echo "$(date '+%F %T') [$SCRIPT_NAME] $*" >&2; }
die() { log "ERREUR : $*"; exit 1; }

while getopts ":d:k:h" opt; do
  case $opt in
    d) DEST=$OPTARG ;;
    k) KEEP=$OPTARG ;;
    h) usage ;;
    :) die "l'option -$OPTARG attend une valeur" ;;
    \?) die "option inconnue : -$OPTARG" ;;
  esac
done
shift $(( OPTIND - 1 ))

[[ $# -eq 1 ]] || usage
SRC=${1%/}

[[ -d "$SRC" ]] || die "le dossier source '$SRC' n'existe pas"
if ! [[ "$KEEP" =~ ^[0-9]+$ ]] || (( KEEP < 1 )); then
  die "-k doit être un entier positif"
fi
mkdir -p "$DEST"

NAME=$(basename "$SRC")
ARCHIVE="$DEST/${NAME}_$(date +%Y%m%d-%H%M%S).tar.gz"

# L'archive est construite dans un fichier temporaire caché, puis renommée
# une fois complète : une archive interrompue ne reste jamais en place.
TMP=$(mktemp "$DEST/.${NAME}_XXXXXX")
trap 'rm -f "$TMP"' EXIT

log "Sauvegarde de $SRC vers $ARCHIVE"
tar -czf "$TMP" -C "$(dirname "$SRC")" "$NAME"
mv "$TMP" "$ARCHIVE"
chmod 640 "$ARCHIVE"
log "Archive créée ($(du -h "$ARCHIVE" | cut -f1))"

# Rotation : les noms contiennent l'horodatage, un tri par nom suffit.
mapfile -t ANCIENNES < <(printf '%s\n' "$DEST/${NAME}"_*.tar.gz | sort -r | tail -n +$(( KEEP + 1 )))
for f in "${ANCIENNES[@]}"; do
  rm -f -- "$f"
  log "Ancienne sauvegarde supprimée : $(basename "$f")"
done

log "Terminé"
```

```bash
chmod +x backup.sh
shellcheck backup.sh
mkdir -p ~/projet && echo "test" > ~/projet/fichier.txt
for i in 1 2 3 4 5; do ./backup.sh -k 3 ~/projet; sleep 1; done
ls -l ~/backups
tar tzf ~/backups/projet_*.tar.gz | head
./backup.sh /nexistepas; echo "Code : $?"
./backup.sh -k abc ~/projet; echo "Code : $?"
```

Quelques choix à expliquer. L'archive est d'abord écrite dans un fichier temporaire, puis renommée par `mv` : un renommage dans le même dossier est instantané, l'archive finale est donc toujours complète. Le `trap` supprime le fichier temporaire si le script s'arrête avant. L'option `-C` de `tar` évite de stocker le chemin absolu de la source dans l'archive. Les archives sont protégées en `640`, car une sauvegarde contient souvent des données sensibles.

</details>
