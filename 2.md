# Chapitre 2 — Shell et navigation

## 1. Terminal, shell et prompt

Trois notions sont souvent confondues.

Le **terminal** (ou émulateur de terminal) est la fenêtre dans laquelle on tape : Windows Terminal, GNOME Terminal, iTerm2... Il se contente d'afficher du texte et de transmettre ce qu'on tape.

Le **shell** est le programme qui tourne dans ce terminal, lit les commandes, les interprète et les exécute. Sous Ubuntu, le shell par défaut est **bash**. Il en existe d'autres : `zsh` (défaut sur macOS), `fish`, `sh` (le shell POSIX minimal), `dash`...

```bash
echo $SHELL        # shell de connexion de l'utilisateur
echo $0            # shell en cours d'exécution
```

Le **prompt** est le texte affiché avant le curseur. Par défaut sous Ubuntu, il ressemble à ceci :

```
student@web:~/projet$
```

On y lit l'utilisateur (`student`), la machine (`web`), le dossier courant (`~/projet`) et le type d'utilisateur : `$` pour un utilisateur normal, `#` pour root.

> 💡 Le nom de machine dans le prompt est précieux quand on jongle entre plusieurs serveurs : prenez l'habitude de le regarder avant de lancer une commande destructrice.

## 2. Anatomie d'une commande

Une commande se compose généralement de trois parties :

```
ls    -l -a    /etc
│     │        │
│     │        └── argument(s) : sur quoi agir
│     └── option(s) : comment agir
└── commande
```

Les options courtes commencent par un tiret et peuvent être regroupées : `ls -l -a` équivaut à `ls -la`. Les options longues commencent par deux tirets et sont plus lisibles : `ls --all`. Certaines options prennent une valeur : `ls --sort=size`, `head -n 5`.

Le shell sépare les éléments par des espaces. Un nom de fichier contenant un espace doit donc être protégé :

```bash
mkdir "mon dossier"     # guillemets
mkdir mon\ dossier      # ou antislash devant l'espace
```

> ⚠️ **Linux est sensible à la casse.** `Fichier.txt`, `fichier.txt` et `FICHIER.TXT` sont trois fichiers différents. Les commandes aussi : `LS` n'existe pas.

## 3. L'arborescence Linux

Sous Linux, il n'y a pas de lettres de lecteur (`C:`, `D:`). Tout part d'une racine unique, notée `/`, et les disques supplémentaires sont « montés » quelque part dans cette arborescence (nous le verrons au chapitre 12).

L'organisation des dossiers suit un standard, le **FHS** (Filesystem Hierarchy Standard). La connaître permet de savoir où chercher sur n'importe quel serveur.

| Dossier | Contenu | Exemple |
|---|---|---|
| `/` | Racine de tout le système | |
| `/etc` | **Fichiers de configuration** du système et des services | `/etc/ssh/sshd_config`, `/etc/hosts` |
| `/home` | Dossiers personnels des utilisateurs | `/home/student` |
| `/root` | Dossier personnel de l'administrateur root | |
| `/var` | **Données variables** : logs, caches, bases de données, files d'attente | `/var/log/`, `/var/lib/mysql/` |
| `/tmp` | Fichiers temporaires, souvent vidés au redémarrage | |
| `/usr` | Programmes et bibliothèques installés par le système | `/usr/bin/python3` |
| `/usr/local` | Logiciels installés manuellement par l'administrateur | |
| `/opt` | Logiciels tiers autonomes | `/opt/google/chrome` |
| `/bin`, `/sbin`, `/lib` | Historiquement les binaires essentiels ; sur Ubuntu récent, ce sont des liens vers `/usr/bin`, `/usr/sbin`, `/usr/lib` | |
| `/dev` | Fichiers représentant les périphériques | `/dev/null`, `/dev/sda` |
| `/proc` | Système de fichiers virtuel : informations sur les processus et le noyau | `/proc/cpuinfo` |
| `/sys` | Système de fichiers virtuel : matériel et paramètres du noyau | |
| `/run` | Données d'exécution (PID, sockets), recréées à chaque démarrage | |
| `/boot` | Noyau et chargeur de démarrage | |
| `/mnt`, `/media` | Points de montage temporaires ou amovibles | `/mnt/c` dans WSL |
| `/srv` | Données servies par le système (sites web, FTP) | |

> 💡 **Les trois dossiers à retenir absolument** pour un développeur : `/etc` (la configuration), `/var/log` (les logs) et `/home` (vos fichiers). Quand un service ne marche pas, on regarde presque toujours dans l'un des deux premiers.

## 4. Se déplacer

### Où suis-je ?

```bash
pwd                # print working directory : affiche le dossier courant
```

### Changer de dossier

```bash
cd /etc            # aller dans /etc
cd ssh             # aller dans le sous-dossier ssh (donc /etc/ssh)
cd ..              # remonter d'un niveau
cd ../..           # remonter de deux niveaux
cd                 # retourner dans son home
cd ~               # idem
cd -               # retourner au dossier précédent (très pratique !)
```

### Chemins absolus et relatifs

Un **chemin absolu** commence par `/` et décrit l'emplacement complet depuis la racine : `/home/student/projet/src`. Il fonctionne quel que soit le dossier où l'on se trouve.

Un **chemin relatif** part du dossier courant : `projet/src` ou `../docs`. Il dépend de l'endroit où l'on est.

Quelques raccourcis à connaître :

| Symbole | Signification |
|---|---|
| `.` | Le dossier courant |
| `..` | Le dossier parent |
| `~` | Le home de l'utilisateur courant |
| `~alice` | Le home de l'utilisateur alice |
| `-` | Le dossier précédent (avec `cd`) |

> 💡 Dans un script, préférez les chemins absolus : un script lancé par cron ou systemd ne démarre pas forcément dans le dossier que vous imaginez.

## 5. Lister le contenu

```bash
ls                 # liste simple
ls -l              # format long : permissions, propriétaire, taille, date
ls -a              # inclut les fichiers cachés
ls -la             # les deux
ls -lh             # tailles lisibles (K, M, G)
ls -lt             # tri par date de modification, plus récent en premier
ls -ltr            # tri par date, plus récent en dernier (idéal pour les logs)
ls -lS             # tri par taille
ls -R              # récursif
ls -ld /etc        # infos sur le dossier lui-même, pas son contenu
```

### Fichiers cachés

Sous Linux, un fichier est caché simplement parce que **son nom commence par un point** : `.bashrc`, `.ssh/`, `.gitignore`. Il n'y a pas d'attribut spécial. Les fichiers de configuration personnels sont presque tous cachés dans votre home.

### Lire la sortie de `ls -l`

```
-rw-r--r-- 1 student student  220 Jan  6 10:32 .bash_logout
drwxr-xr-x 2 student student 4096 Jan  6 10:40 projet
lrwxrwxrwx 1 root    root       7 Apr 22  2024 /bin -> usr/bin
│└───┬───┘ │ └──┬──┘ └──┬──┘ └┬┘ └─────┬────┘ └──┬──┘
│    │     │    │       │     │        │         └ nom
│    │     │    │       │     │        └ date de modification
│    │     │    │       │     └ taille en octets
│    │     │    │       └ groupe propriétaire
│    │     │    └ utilisateur propriétaire
│    │     └ nombre de liens
│    └ permissions (chapitre 4)
└ type de fichier
```

Le premier caractère indique le type :

| Caractère | Type |
|---|---|
| `-` | Fichier ordinaire |
| `d` | Dossier (directory) |
| `l` | Lien symbolique |
| `c` | Périphérique caractère (`/dev/null`, terminal) |
| `b` | Périphérique bloc (disque) |
| `s` | Socket |
| `p` | Pipe nommé |

### Autres commandes utiles

```bash
tree ~/projet      # affiche l'arborescence (sudo apt install tree)
tree -L 2 /etc     # limité à 2 niveaux
file /bin/ls       # devine le type réel d'un fichier
file photo.jpg
stat fichier.txt   # toutes les métadonnées : taille, dates, inode, droits
```

> 💡 Sous Linux, **l'extension ne compte pas**. Un fichier `script.txt` peut parfaitement être un exécutable. La commande `file` regarde le contenu, pas le nom.

## 6. Créer, copier, déplacer, supprimer

### Créer

```bash
mkdir projet                       # crée un dossier
mkdir -p projet/src/utils          # crée toute l'arborescence si nécessaire
touch notes.txt                    # crée un fichier vide (ou met à jour sa date)
```

### Copier

```bash
cp source.txt copie.txt            # copie un fichier
cp fichier.txt dossier/            # copie dans un dossier
cp -r projet/ projet-backup/       # copie récursive d'un dossier
cp -a projet/ projet-backup/       # copie en préservant droits, dates, liens
cp -i source.txt cible.txt         # demande confirmation avant d'écraser
```

### Déplacer et renommer

Sous Linux, renommer et déplacer sont la même opération :

```bash
mv ancien.txt nouveau.txt          # renomme
mv fichier.txt dossier/            # déplace
mv dossier/ /tmp/                  # déplace un dossier
```

### Supprimer

```bash
rm fichier.txt                     # supprime un fichier
rm -i fichier.txt                  # demande confirmation
rmdir dossier                      # supprime un dossier vide
rm -r dossier                      # supprime un dossier et tout son contenu
rm -rf dossier                     # idem, sans jamais demander
```

> ⚠️ **Il n'y a pas de corbeille.** Un fichier supprimé avec `rm` est perdu. `rm -rf` ne pose aucune question et ne pardonne aucune faute de frappe. Un espace mal placé dans `rm -rf / tmp/test` (au lieu de `/tmp/test`) peut effacer tout le système. Relisez toujours une commande `rm -rf` avant de valider, surtout avec `sudo`.

### Liens symboliques

Un lien symbolique est un raccourci vers un autre fichier ou dossier :

```bash
ln -s /var/log/nginx ~/logs-nginx  # crée un lien
ls -l ~/logs-nginx                 # montre la cible
readlink -f ~/logs-nginx           # affiche le chemin réel
```

C'est très utilisé en administration : `/etc/nginx/sites-enabled/` contient par exemple des liens vers `/etc/nginx/sites-available/`.

## 7. Les jokers (globbing) et l'expansion

Le shell sait remplacer des motifs par une liste de fichiers **avant** d'exécuter la commande.

| Motif | Correspond à | Exemple |
|---|---|---|
| `*` | N'importe quelle suite de caractères | `ls *.log` |
| `?` | Exactement un caractère | `ls fichier?.txt` → `fichier1.txt`, `fichierA.txt` |
| `[abc]` | Un caractère parmi la liste | `ls [abc]*` |
| `[0-9]` | Un caractère dans l'intervalle | `ls log[0-9].txt` |

```bash
ls /etc/*.conf             # tous les .conf directement dans /etc
rm *.tmp                   # supprime tous les .tmp du dossier courant
cp *.jpg ~/photos/
```

### L'expansion d'accolades

Les accolades génèrent des listes, qu'un fichier existe ou non :

```bash
mkdir -p projet/{src,tests,docs}
touch fichier{1..5}.txt            # fichier1.txt ... fichier5.txt
cp config.yml{,.bak}               # équivaut à : cp config.yml config.yml.bak
echo {a..e}                        # a b c d e
```

> 💡 Pour voir ce que le shell va réellement exécuter, préfixez la commande par `echo` : `echo rm *.log` affiche la liste des fichiers concernés sans rien supprimer.

## 8. Rechercher des fichiers avec `find`

`find` parcourt une arborescence et sélectionne les fichiers selon des critères. Sa syntaxe générale est `find <où> <critères> <action>`.

### Par nom

```bash
find /etc -name "hosts"            # nom exact
find /etc -name "*.conf"           # avec joker (guillemets obligatoires)
find ~ -iname "readme*"            # insensible à la casse
```

### Par type

```bash
find /var/log -type f              # fichiers seulement
find ~ -type d -name ".git"        # dossiers seulement
find /usr/bin -type l              # liens symboliques
```

### Par taille

```bash
find / -type f -size +100M         # plus de 100 Mo
find ~ -type f -size -1k           # moins de 1 Ko
find ~ -type f -empty              # fichiers vides
```

### Par date

```bash
find /var/log -mtime -1            # modifiés il y a moins de 24 h
find /tmp -mtime +7                # modifiés il y a plus de 7 jours
find ~ -mmin -30                   # modifiés il y a moins de 30 minutes
find ~ -newer reference.txt        # plus récents qu'un fichier donné
```

### Limiter la profondeur et combiner

```bash
find /etc -maxdepth 1 -name "*.conf"
find /var/log -type f -name "*.log" -size +1M      # ET implicite
find ~ \( -name "*.jpg" -o -name "*.png" \)         # OU
find ~ -type f ! -name "*.txt"                      # NON
```

### Agir sur les résultats

```bash
find /tmp -name "*.tmp" -delete                     # supprimer
find ~ -name "*.sh" -exec chmod +x {} \;            # une commande par fichier
find /var/log -name "*.log" -exec ls -lh {} +       # une commande pour tous
```

Avec `-exec`, les accolades `{}` sont remplacées par le nom du fichier trouvé. Terminer par `\;` lance la commande une fois par fichier ; terminer par `+` regroupe tous les fichiers en un seul appel, ce qui est beaucoup plus rapide.

> 💡 Quand on cherche dans tout le système, `find` affiche de nombreuses erreurs « Permission denied ». On les masque en redirigeant la sortie d'erreur : `find / -name "sshd_config" 2>/dev/null`. Nous détaillerons les redirections au chapitre 3.

> ⚠️ Avant un `find ... -delete`, lancez **toujours** la même commande sans `-delete` pour vérifier la liste.

### Trouver une commande

```bash
which python3          # chemin de l'exécutable qui sera lancé
type ls                # indique si c'est un alias, une commande interne, un fichier
type cd                # cd est une commande interne du shell (builtin)
command -v docker      # version portable de which, idéale dans les scripts
```

### `locate` : la recherche instantanée

`locate` interroge une base de données pré-calculée, ce qui le rend quasi instantané, mais la base peut être en retard sur la réalité.

```bash
sudo apt install plocate
sudo updatedb                  # met à jour la base
locate sshd_config
```

## 9. Trouver de l'aide

Personne ne connaît toutes les options de toutes les commandes. Savoir chercher l'information est plus important que de la mémoriser.

### `--help`

La plupart des commandes affichent un résumé de leur utilisation :

```bash
ls --help
cp --help | less
```

### `man` : le manuel

```bash
man ls
man find
```

Navigation dans une page de manuel :

| Touche | Action |
|---|---|
| `Espace` / `b` | Page suivante / précédente |
| `↑` `↓` | Ligne par ligne |
| `/mot` | Rechercher « mot » |
| `n` / `N` | Occurrence suivante / précédente |
| `g` / `G` | Début / fin |
| `q` | Quitter |

Le manuel est découpé en **sections** :

| Section | Contenu |
|---|---|
| 1 | Commandes utilisateur |
| 2 | Appels système |
| 3 | Fonctions de bibliothèques (C) |
| 5 | **Formats de fichiers de configuration** |
| 7 | Divers (conventions, protocoles) |
| 8 | Commandes d'administration |

Un même nom peut exister dans plusieurs sections :

```bash
man passwd             # la commande passwd (section 1)
man 5 passwd           # le format du fichier /etc/passwd
man 5 sshd_config      # toutes les options de configuration de SSH
man 7 hier             # description de l'arborescence Linux !
```

> 💡 La section 5 est une mine d'or pour l'administration : presque chaque fichier de configuration y est documenté.

### Chercher une commande par mot-clé

```bash
man -k compress        # ou : apropos compress
man -k "list directory"
```

### Les commandes internes du shell

Les commandes comme `cd`, `export`, `alias` ou `history` sont intégrées à bash et n'ont pas de page `man` propre. On utilise `help` :

```bash
help cd
help history
```

### `tldr` : des exemples concrets

`tldr` affiche des exemples d'utilisation courants, là où `man` est exhaustif mais parfois indigeste :

```bash
sudo apt install tldr
tldr --update
tldr tar
tldr find
```

## 10. Raccourcis clavier et historique

Ces raccourcis font la différence entre quelqu'un qui subit le terminal et quelqu'un qui y est à l'aise.

### L'autocomplétion avec `Tab`

C'est **le** raccourci le plus important. Une pression sur `Tab` complète un nom de commande, de fichier ou de dossier. Deux pressions affichent toutes les possibilités s'il y en a plusieurs. Au-delà du gain de temps, l'autocomplétion évite les fautes de frappe : si `Tab` ne complète pas, c'est que le chemin n'existe pas.

### Édition de la ligne

| Raccourci | Action |
|---|---|
| `Ctrl+A` / `Ctrl+E` | Début / fin de ligne |
| `Alt+B` / `Alt+F` | Mot précédent / suivant |
| `Ctrl+W` | Efface le mot avant le curseur |
| `Ctrl+U` | Efface du curseur jusqu'au début de la ligne |
| `Ctrl+K` | Efface du curseur jusqu'à la fin de la ligne |
| `Ctrl+Y` | Colle ce qui vient d'être effacé |
| `Ctrl+L` | Efface l'écran (comme `clear`) |

### Contrôle des programmes

| Raccourci | Action |
|---|---|
| `Ctrl+C` | Interrompt la commande en cours |
| `Ctrl+D` | Fin de saisie ; sur une ligne vide, ferme le shell |
| `Ctrl+Z` | Suspend la commande en cours (chapitre 5) |

### L'historique

```bash
history                # affiche l'historique numéroté
history | tail -20     # les 20 dernières commandes
!42                    # relance la commande numéro 42
!!                     # relance la dernière commande
sudo !!                # relance la dernière commande avec sudo
!$                     # dernier argument de la commande précédente
```

Exemple typique :

```bash
mkdir -p ~/projet/src/utils
cd !$                  # équivaut à : cd ~/projet/src/utils
```

| Raccourci | Action |
|---|---|
| `↑` / `↓` | Commande précédente / suivante |
| `Ctrl+R` | **Recherche dans l'historique** : tapez un morceau de commande, `Ctrl+R` à nouveau pour remonter, `Entrée` pour exécuter, `→` pour éditer |
| `Alt+.` | Insère le dernier argument de la commande précédente (répéter pour remonter) |

> 💡 `Ctrl+R` est probablement le raccourci le plus rentable après `Tab`. Prenez l'habitude de l'utiliser au lieu de marteler la flèche du haut.

## 11. Personnaliser son shell

### Les alias

Un alias est un raccourci pour une commande :

```bash
alias ll='ls -lah'
alias ..='cd ..'
alias gs='git status'
alias                  # liste les alias définis
unalias ll             # supprime un alias
```

Un alias défini ainsi disparaît à la fermeture du terminal. Pour le rendre permanent, on l'ajoute au fichier `~/.bashrc`, lu à chaque ouverture d'un shell interactif :

```bash
echo "alias ll='ls -lah'" >> ~/.bashrc
source ~/.bashrc       # recharge la configuration sans rouvrir le terminal
```

### La variable `PATH`

Quand vous tapez `ls`, le shell cherche un exécutable nommé `ls` dans chacun des dossiers listés dans la variable `PATH`, dans l'ordre :

```bash
echo $PATH
# /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

C'est pour cela qu'un script situé dans le dossier courant doit être lancé avec `./script.sh` : le dossier courant n'est pas dans le `PATH`, et c'est volontaire pour des raisons de sécurité.

Pour ajouter un dossier personnel au `PATH` de façon permanente :

```bash
mkdir -p ~/bin
echo 'export PATH="$HOME/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

### Exercice 2.2 — Créer une structure de projet (niveau de base)

En **une seule commande**, créez cette arborescence dans votre home :

```
app/
├── src/
│   ├── api/
│   └── models/
├── tests/
├── docs/
└── config/
```

Puis créez en une seule commande les fichiers `test_1.py` à `test_5.py` dans `tests/`. Faites une copie de sauvegarde de `app` nommée `app.bak`, puis supprimez-la.

<details>
<summary>Solution</summary>

```bash
mkdir -p ~/app/{src/{api,models},tests,docs,config}
touch ~/app/tests/test_{1..5}.py
tree ~/app

rm -r ~/app.bak
```

### Exercice 2.3 — Maîtriser `find` (niveau intermédiaire)

Trouvez :

1. tous les fichiers `.conf` situés **directement** dans `/etc` (pas dans les sous-dossiers) ;
2. tous les fichiers de `/var/log` modifiés dans les dernières 24 heures ;
3. tous les fichiers de plus de 10 Mo sous `/usr`, avec leur taille affichée ;
4. l'emplacement du fichier de configuration du serveur SSH (dans un conteneur du lab), sans afficher les erreurs de permission.

<details>
<summary>Solution</summary>

```bash
find /etc -maxdepth 1 -type f -name "*.conf"
sudo find /var/log -type f -mtime -1
find /usr -type f -size +10M -exec ls -lh {} +
docker compose exec web find / -name "sshd_config" 2>/dev/null
```

</details>
