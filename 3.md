# Chapitre 3 — Fichiers et manipulation de texte

## 1. La philosophie Unix

Les outils Unix suivent un principe simple : **chaque programme fait une seule chose, et la fait bien**. `grep` filtre des lignes, `sort` trie, `wc` compte. Aucun ne sait tout faire, mais on peut les **enchaîner** pour obtenir des traitements puissants.

Le texte est le format universel qui circule entre ces programmes. C'est pour ça que la quasi-totalité de la configuration et des logs sous Linux sont de simples fichiers texte : on peut tous les traiter avec les mêmes outils.

```bash
# Les 5 adresses IP qui font le plus de requêtes sur un serveur web :
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -5
```

À la fin de ce chapitre, cette ligne vous paraîtra évidente.

## 2. Lire des fichiers

### `cat` : afficher tout le contenu

```bash
cat /etc/hostname
cat -n /etc/passwd         # avec numéros de ligne
cat fichier1 fichier2      # concatène plusieurs fichiers (d'où son nom)
```

`cat` affiche tout d'un coup : parfait pour un petit fichier, inutilisable pour un log de 100 000 lignes.

### `less` : naviguer dans un gros fichier

```bash
less /var/log/syslog
```

`less` ne charge pas tout le fichier en mémoire et permet de naviguer. Les touches sont les mêmes que pour `man` (c'est d'ailleurs `less` qui affiche les pages de manuel) :

| Touche | Action |
|---|---|
| `Espace` / `b` | Page suivante / précédente |
| `g` / `G` | Début / fin du fichier |
| `/motif` | Rechercher vers le bas |
| `?motif` | Rechercher vers le haut |
| `n` / `N` | Occurrence suivante / précédente |
| `F` | Suivre le fichier en temps réel (`Ctrl+C` pour arrêter) |
| `q` | Quitter |

Options utiles : `less -N` (numéros de ligne), `less -S` (ne pas replier les lignes longues, pratique pour les logs).

### `head` et `tail` : le début et la fin

```bash
head fichier.log           # les 10 premières lignes
head -n 3 fichier.log      # les 3 premières lignes
tail fichier.log           # les 10 dernières lignes
tail -n 50 fichier.log     # les 50 dernières lignes
tail -n +100 fichier.log   # à partir de la ligne 100
```

### `tail -f` : suivre un log en direct

C'est l'une des commandes les plus utilisées en production :

```bash
tail -f /var/log/nginx/access.log
```

`tail -f` affiche les nouvelles lignes au fur et à mesure qu'elles sont écrites. On l'arrête avec `Ctrl+C`.

> 💡 Préférez `tail -F` (majuscule) : si le fichier est remplacé, par exemple lors de la rotation des logs, `tail -F` le rouvre automatiquement alors que `tail -f` continue à surveiller l'ancien fichier et n'affiche plus rien.

### `wc` : compter

```bash
wc fichier.txt             # lignes, mots, octets
wc -l fichier.txt          # nombre de lignes uniquement
wc -w fichier.txt          # nombre de mots
```

## 3. Les flux standard

Chaque processus Linux dispose de trois flux ouverts par défaut, identifiés par un numéro (un *descripteur de fichier*) :

| Numéro | Nom | Rôle | Par défaut |
|---|---|---|---|
| 0 | **stdin** | Entrée standard | Le clavier |
| 1 | **stdout** | Sortie standard : les résultats | Le terminal |
| 2 | **stderr** | Sortie d'erreur : les messages d'erreur | Le terminal |

```
              ┌──────────────┐
  stdin (0) ─►│   commande   ├─► stdout (1)
              │              ├─► stderr (2)
              └──────────────┘
```

Les résultats et les erreurs arrivent tous les deux dans le terminal, mais ce sont **deux canaux distincts**. C'est ce qui permet, par exemple, d'envoyer les résultats dans un fichier tout en voyant les erreurs à l'écran.

```bash
ls /etc/hostname /inexistant
# /etc/hostname                                      ← stdout
# ls: cannot access '/inexistant': No such file...   ← stderr
```

## 4. Les redirections

### Rediriger la sortie standard

```bash
ls /etc > liste.txt        # écrit dans le fichier (l'écrase s'il existe)
ls /var >> liste.txt       # ajoute à la fin du fichier
```

> ⚠️ `>` **écrase le fichier sans prévenir**. Une faute de frappe entre `>` et `>>` sur un fichier important, et son contenu est perdu. L'option `set -o noclobber` (à mettre dans `~/.bashrc`) empêche `>` d'écraser un fichier existant ; on force alors avec `>|`.

### Rediriger les erreurs

```bash
ls /etc /inexistant 2> erreurs.txt           # seules les erreurs vont dans le fichier
ls /etc /inexistant > ok.txt 2> erreurs.txt  # séparés
find / -name "*.conf" 2>/dev/null            # erreurs jetées
```

`/dev/null` est un fichier spécial qui avale tout ce qu'on y écrit. C'est la poubelle du système.

### Regrouper sortie et erreurs

```bash
commande > tout.txt 2>&1   # stdout et stderr dans le même fichier
commande &> tout.txt       # raccourci bash équivalent
commande > /dev/null 2>&1  # rendre une commande totalement silencieuse
```

`2>&1` signifie « envoie le flux 2 au même endroit que le flux 1 ». **L'ordre compte** : les redirections sont lues de gauche à droite.

```bash
commande > fichier 2>&1    # ✅ stdout vers le fichier, puis stderr au même endroit
commande 2>&1 > fichier    # ❌ stderr vers le terminal (où était stdout), puis stdout vers le fichier
```

### Rediriger l'entrée

```bash
wc -l < /etc/passwd        # le fichier est envoyé sur stdin
```

### Le here-document

Pratique pour écrire un fichier de plusieurs lignes directement depuis le terminal ou un script :

```bash
cat > config.ini << EOF
[database]
host=localhost
port=5432
EOF
```

Tout ce qui se trouve entre `<< EOF` et la ligne `EOF` est envoyé sur l'entrée de la commande. Les variables comme `$HOME` y sont remplacées ; pour les garder telles quelles, on écrit `<< 'EOF'`.

### Le piège de `sudo` et des redirections

```bash
sudo echo "127.0.0.1 monapp.local" >> /etc/hosts
# bash: /etc/hosts: Permission denied
```

Pourquoi ? La redirection `>>` est effectuée par **votre shell**, qui tourne avec vos droits, et pas par `sudo`. `sudo` ne s'applique qu'à `echo`. La solution est `tee` :

```bash
echo "127.0.0.1 monapp.local" | sudo tee -a /etc/hosts
```

## 5. Les pipes

Le pipe `|` branche la sortie standard d'une commande sur l'entrée standard de la suivante :

```bash
cat /etc/passwd | wc -l
ls -l /etc | less
history | grep docker
```

```
  commande1 ──stdout──► │ ──stdin──► commande2 ──stdout──► │ ──stdin──► commande3
```

Seul **stdout** passe dans le pipe ; les erreurs continuent de s'afficher dans le terminal. Pour les faire passer aussi : `commande 2>&1 | grep erreur`, ou en bash `commande |& grep erreur`.

### `tee` : voir et enregistrer en même temps

`tee` duplique son entrée : il l'écrit dans un fichier **et** la renvoie sur sa sortie.

```bash
./deploy.sh | tee deploy.log            # on voit la sortie ET on la garde
./deploy.sh 2>&1 | tee -a deploy.log    # avec les erreurs, en ajout
```

> 💡 Pour lire une chaîne de pipes, lisez-la de gauche à droite comme une phrase, et construisez-la **étape par étape** : lancez la première commande, regardez le résultat, ajoutez un pipe, recommencez. C'est la méthode la plus sûre, même pour les experts.

## 6. `grep` : filtrer des lignes

`grep` affiche les lignes qui contiennent un motif.

```bash
grep "error" app.log               # lignes contenant « error »
grep -i "error" app.log            # insensible à la casse
grep -v "DEBUG" app.log            # lignes NE contenant PAS « DEBUG »
grep -n "error" app.log            # avec numéro de ligne
grep -c "error" app.log            # nombre de lignes correspondantes
grep -w "root" /etc/passwd         # mot entier (pas « chroot »)
grep -o "[0-9]\+ms" app.log        # affiche uniquement la partie correspondante
```

### Rechercher dans plusieurs fichiers

```bash
grep -r "DATABASE_URL" ~/projet/           # récursif
grep -rl "TODO" ~/projet/src/              # juste les noms de fichiers
grep -r --include="*.py" "import os" .     # filtrer par type de fichier
```

### Afficher le contexte

Très utile pour comprendre ce qui s'est passé autour d'une erreur :

```bash
grep -A 3 "Exception" app.log      # 3 lignes après (After)
grep -B 2 "Exception" app.log      # 2 lignes avant (Before)
grep -C 5 "Exception" app.log      # 5 lignes avant et après (Context)
```

### Les expressions régulières

`grep` accepte des expressions régulières. Avec l'option `-E` (expressions étendues), la syntaxe est la plus proche de celle des langages de programmation :

| Motif | Signification | Exemple |
|---|---|---|
| `^` | Début de ligne | `^#` : lignes de commentaire |
| `$` | Fin de ligne | `\.conf$` |
| `.` | N'importe quel caractère | `h.t` : hat, hot, h9t |
| `*` | 0 fois ou plus l'élément précédent | `ab*c` : ac, abc, abbc |
| `+` | 1 fois ou plus | `[0-9]+` |
| `?` | 0 ou 1 fois | `https?` |
| `[abc]`, `[a-z]` | Un caractère parmi | `[0-9]` |
| `[^abc]` | Un caractère sauf | `[^ ]+` : un mot sans espace |
| `{n,m}` | Entre n et m fois | `[0-9]{1,3}` |
| `a\|b` | Alternative : a ou b | `-E "error\|fatal"` |
| `( )` | Groupe | `-E "(GET\|POST) /api"` |

```bash
grep -E "^(root|student):" /etc/passwd
grep -E "ERROR|FATAL" app.log
grep -Eo "[0-9]{1,3}(\.[0-9]{1,3}){3}" access.log     # extraire des adresses IP
grep -v -E "^\s*(#|$)" /etc/ssh/sshd_config           # config sans commentaires ni lignes vides
```

> 💡 Cette dernière commande est un classique de l'administrateur : les fichiers de configuration font souvent des centaines de lignes de commentaires pour une dizaine de lignes réellement actives.

### Les fichiers compressés

Les anciens logs sont généralement compressés (`syslog.2.gz`). Les variantes `zcat`, `zless` et `zgrep` les lisent sans les décompresser :

```bash
zgrep "error" /var/log/syslog.2.gz
```

## 7. Découper, trier, compter

### `cut` : extraire des colonnes

```bash
cut -d: -f1 /etc/passwd            # 1er champ, séparateur « : »
cut -d: -f1,7 /etc/passwd          # champs 1 et 7
cut -d, -f2-4 data.csv             # champs 2 à 4
cut -c1-10 fichier.txt             # caractères 1 à 10
```

`cut` fonctionne bien avec un séparateur unique et fiable (`:`, `,`, tabulation). Pour des colonnes séparées par un nombre variable d'espaces, `awk` est plus adapté.

### `sort` : trier

```bash
sort noms.txt                      # tri alphabétique
sort -r noms.txt                   # ordre inverse
sort -n nombres.txt                # tri numérique (sinon 10 arrive avant 9)
sort -h tailles.txt                # tri de tailles lisibles (1K, 2M, 3G)
sort -u noms.txt                   # tri + suppression des doublons
sort -t: -k3 -n /etc/passwd        # trier sur le 3e champ, séparateur « : »
sort -k2,2 -k1,1 fichier           # tri sur la colonne 2, puis la colonne 1
```

```bash
du -sh /var/* 2>/dev/null | sort -h    # dossiers de /var classés par taille
```

### `uniq` : dédoublonner et compter

```bash
uniq fichier                       # supprime les doublons CONSÉCUTIFS
uniq -c fichier                    # compte les occurrences
uniq -d fichier                    # n'affiche que les lignes en double
```

> ⚠️ `uniq` ne supprime que les doublons **qui se suivent**. Il faut donc presque toujours trier avant : `sort | uniq -c`.

Le motif « compter et classer » est à connaître par cœur :

```bash
... | sort | uniq -c | sort -rn | head
```

Il se lit : trier pour regrouper les valeurs identiques, compter chaque groupe, trier par nombre décroissant, garder les premiers.

### `tr` : remplacer des caractères

```bash
echo "hello" | tr a-z A-Z          # HELLO
echo "a,b,c" | tr ',' '\n'         # un élément par ligne
tr -d '\r' < windows.txt > unix.txt    # supprimer les retours chariot Windows
tr -s ' ' < fichier                # compresser les espaces multiples
```

> 💡 Le `tr -d '\r'` sauve régulièrement la vie : un script bash écrit sous Windows contient des fins de ligne `\r\n` qui provoquent des erreurs incompréhensibles comme `$'\r': command not found`. C'est un piège fréquent avec WSL.

## 8. `awk` : traiter des colonnes

`awk` est un véritable petit langage de programmation, mais 90 % de son usage courant tient en quelques motifs. Il lit le texte ligne par ligne, découpe chaque ligne en champs (séparés par des espaces par défaut) et les rend accessibles dans `$1`, `$2`... `$0` représente la ligne entière et `NF` le nombre de champs.

### Afficher des colonnes

```bash
awk '{print $1}' access.log                # 1re colonne
awk '{print $1, $9}' access.log            # colonnes 1 et 9
awk '{print $NF}' fichier                  # dernière colonne
awk -F: '{print $1, $7}' /etc/passwd       # séparateur « : »
```

Contrairement à `cut`, `awk` gère naturellement des colonnes séparées par un nombre variable d'espaces, comme dans la sortie de `ps`, `df` ou `ls -l`.

```bash
df -h | awk '{print $5, $6}'               # taux d'occupation et point de montage
```

### Filtrer

```bash
awk '$9 == 500' access.log                 # lignes dont la colonne 9 vaut 500
awk '$9 >= 400 {print $1, $7}' access.log  # IP et URL des erreurs
awk -F: '$3 >= 1000 {print $1}' /etc/passwd    # utilisateurs « humains »
awk '/ERROR/ {print $2}' app.log           # lignes contenant ERROR
awk 'NR > 1' data.csv                      # sauter la ligne d'en-tête
```

### Calculer

```bash
awk '{total += $10} END {print total}' access.log              # somme
awk '{s += $10; n++} END {print s/n}' access.log               # moyenne
awk '{count[$9]++} END {for (c in count) print c, count[c]}' access.log   # comptage par valeur
```

Le bloc `END` s'exécute une seule fois, après la dernière ligne. `count[$9]++` utilise un tableau associatif, comme un dictionnaire en Python.

### Mettre en forme

```bash
awk -F: '{printf "%-20s %s\n", $1, $7}' /etc/passwd
```

## 9. `sed` : modifier du texte à la volée

`sed` (stream editor) transforme un flux de texte. Son usage principal est la substitution.

### Substituer

```bash
sed 's/foo/bar/' fichier           # remplace la 1re occurrence de chaque ligne
sed 's/foo/bar/g' fichier          # remplace toutes les occurrences
sed 's/foo/bar/gi' fichier         # insensible à la casse
sed 's|/var/www|/srv/www|g' conf   # autre séparateur, pratique avec des chemins
```

Par défaut, `sed` **n'écrit pas dans le fichier** : il affiche le résultat. C'est parfait pour tester.

### Modifier le fichier directement

```bash
sed -i 's/Port 22/Port 2222/' sshd_config          # modifie le fichier
sed -i.bak 's/Port 22/Port 2222/' sshd_config      # en gardant une sauvegarde .bak
```

> ⚠️ Testez **toujours** votre commande `sed` sans `-i` avant de l'appliquer, et utilisez `-i.bak` sur les fichiers importants.

### Supprimer et afficher des lignes

```bash
sed '/^#/d' fichier                # supprime les lignes de commentaire
sed '/^$/d' fichier                # supprime les lignes vides
sed -n '10,20p' fichier            # affiche les lignes 10 à 20
sed -n '/START/,/END/p' fichier    # affiche d'un motif à un autre
```

### Un cas concret : modifier une configuration

```bash
# Activer une option commentée dans un fichier de configuration
sed -i.bak 's/^#\?PasswordAuthentication .*/PasswordAuthentication no/' /etc/ssh/sshd_config
```

C'est exactement ce que font de nombreux scripts d'installation et outils d'automatisation.

## 10. Autres outils utiles

### `xargs` : transformer une liste en arguments

Certaines commandes ne lisent pas leur entrée standard mais attendent des arguments. `xargs` fait le pont :

```bash
find . -name "*.log" | xargs grep "ERROR"
find . -name "*.tmp" | xargs rm
cat serveurs.txt | xargs -I{} ping -c 1 {}
```

Si des noms de fichiers peuvent contenir des espaces, utilisez le séparateur nul :

```bash
find . -name "*.log" -print0 | xargs -0 grep "ERROR"
```

### `diff` : comparer deux fichiers

```bash
diff config.yml config.yml.bak
diff -u ancien.conf nouveau.conf           # format unifié, comme git diff
diff <(sort liste1.txt) <(sort liste2.txt) # comparer des sorties de commandes
```

### `column` : aligner une sortie

```bash
column -t -s: /etc/passwd | less -S
mount | column -t
```

## 11. Archives et compression

Les archives `.tar.gz` sont omniprésentes : sauvegardes, livraisons de logiciels, logs archivés.

```bash
tar czf archive.tar.gz dossier/            # créer une archive compressée
tar tzf archive.tar.gz                     # lister le contenu
tar xzf archive.tar.gz                     # extraire dans le dossier courant
tar xzf archive.tar.gz -C /tmp/            # extraire ailleurs
```

Les lettres se lisent ainsi : `c` pour créer, `x` pour extraire, `t` pour lister, `z` pour la compression gzip, `f` pour indiquer le nom du fichier (toujours en dernier), et `v` (optionnel) pour afficher les fichiers traités.

```bash
gzip fichier.log           # compresse → fichier.log.gz (supprime l'original)
gunzip fichier.log.gz      # décompresse
```

## 12. Éditer un fichier dans le terminal

Sur un serveur, pas d'interface graphique : il faut savoir éditer un fichier en ligne de commande.

### `nano` : le plus simple

```bash
nano fichier.txt
```

Les raccourcis sont affichés en bas de l'écran (`^` signifie `Ctrl`) :

| Raccourci | Action |
|---|---|
| `Ctrl+O` puis `Entrée` | Enregistrer |
| `Ctrl+X` | Quitter |
| `Ctrl+W` | Rechercher |
| `Ctrl+K` / `Ctrl+U` | Couper / coller une ligne |
| `Alt+U` | Annuler |

### `vim` : le minimum vital

`vim` (ou `vi`) est installé sur presque tous les serveurs, y compris les plus minimalistes. Même si vous préférez `nano`, vous finirez un jour sur une machine où seul `vi` est disponible, ou `vim` s'ouvrira tout seul (lors d'un `git commit`, d'un `crontab -e`...). Il faut au moins savoir en sortir.

`vim` fonctionne par **modes**. Au lancement, on est en mode *normal* : les touches sont des commandes, pas du texte.

| Touche | Action |
|---|---|
| `i` | Passer en mode insertion (on peut taper du texte) |
| `Échap` | Revenir en mode normal |
| `:w` | Enregistrer |
| `:q` | Quitter |
| `:wq` ou `:x` | Enregistrer et quitter |
| `:q!` | **Quitter sans enregistrer** (la sortie de secours) |
| `/motif` | Rechercher |
| `dd` | Supprimer la ligne |
| `u` | Annuler |

> 💡 En cas de panique dans `vim` : `Échap`, puis `:q!`, puis `Entrée`. Vous êtes sorti, rien n'a été modifié.

## 13. Exercices

Les exercices 3.3 à 3.6 utilisent un log de serveur web fictif, `~/logs/access.log`, généré par le formateur (voir les notes en fin de chapitre). Chaque ligne suit le format standard de nginx et Apache :

```
192.168.1.42 - - [15/Sep/2026:10:15:32 +0200] "GET /api/users HTTP/1.1" 200 1234 "-" "Mozilla/5.0 ..."
```

Avec `awk`, les colonnes utiles sont : `$1` l'adresse IP, `$4` la date et l'heure, `$6` la méthode (précédée d'un guillemet), `$7` l'URL, `$9` le code HTTP et `$10` la taille de la réponse en octets.

### Exercice 3.1 — Redirections (niveau de base)

1. Enregistrez la liste des fichiers de `/etc` dans `~/etc.txt`.
2. Ajoutez-y la liste des fichiers de `/var`.
3. Lancez `ls /etc /nexistepas` en envoyant les résultats dans `ok.txt` et les erreurs dans `ko.txt`.
4. Lancez la même commande en envoyant tout dans `tout.txt`.
5. Ajoutez la ligne `127.0.0.1 monapp.local` à la fin de `/etc/hosts`.

<details>
<summary>Solution</summary>

```bash
ls /etc > ~/etc.txt
ls /var >> ~/etc.txt
ls /etc /nexistepas > ok.txt 2> ko.txt
ls /etc /nexistepas > tout.txt 2>&1
echo "127.0.0.1 monapp.local" | sudo tee -a /etc/hosts
```

</details>

### Exercice 3.2 — Explorer `/etc/passwd` (niveau de base)

Chaque ligne de `/etc/passwd` décrit un compte : `nom:x:UID:GID:description:home:shell`.

1. Affichez uniquement les noms des comptes.
2. Combien de comptes existe-t-il ?
3. Quels comptes utilisent `/bin/bash` comme shell ?
4. Affichez les comptes classés par UID décroissant.
5. Quels shells différents sont utilisés, et par combien de comptes chacun ?

<details>
<summary>Solution</summary>

```bash
cut -d: -f1 /etc/passwd
wc -l < /etc/passwd
grep "/bin/bash$" /etc/passwd | cut -d: -f1
sort -t: -k3 -rn /etc/passwd
cut -d: -f7 /etc/passwd | sort | uniq -c | sort -rn
```

</details>

### Exercice 3.3 — Premiers pas dans le log (niveau de base)

1. Combien de requêtes le log contient-il ?
2. Affichez les 5 premières et les 5 dernières lignes.
3. Combien de requêtes ont abouti à une erreur 500 ?
4. Affichez toutes les requêtes vers `/admin`.
5. Combien de requêtes ont été faites avec `curl` ?

<details>
<summary>Solution</summary>

```bash
wc -l ~/logs/access.log
head -5 ~/logs/access.log
tail -5 ~/logs/access.log
awk '$9 == 500' ~/logs/access.log | wc -l
grep '"GET /admin' ~/logs/access.log     # ou : awk '$7 == "/admin"'
grep -c "curl/" ~/logs/access.log
```

</details>

### Exercice 3.4 — Statistiques (niveau intermédiaire)

1. Quelles sont les 10 adresses IP qui font le plus de requêtes ?
2. Répartition des requêtes par code HTTP.
3. Quelles sont les 5 URLs les plus demandées ?
4. Quelles URLs provoquent des erreurs 404 ? Classez-les par fréquence.
5. Combien d'adresses IP différentes ont visité le site ?

<details>
<summary>Solution</summary>

```bash
awk '{print $1}' ~/logs/access.log | sort | uniq -c | sort -rn | head -10
awk '{print $9}' ~/logs/access.log | sort | uniq -c | sort -rn

awk '$9 == 404 {print $7}' ~/logs/access.log | sort | uniq -c | sort -rn

### Exercice 3.5 — Enquête de sécurité (niveau intermédiaire)

Quelque chose de suspect s'est produit sur ce serveur.

1. Une adresse IP a fait un nombre anormal de tentatives de connexion échouées (`POST /api/login` avec un code 401). Laquelle, et combien de tentatives ?
2. À quelle heure ces tentatives ont-elles eu lieu ?
3. Quel outil (user agent) cette adresse utilisait-elle ?
4. Des robots ont tenté d'accéder à des fichiers sensibles (`/.env`, `/wp-login.php`). Listez les adresses IP concernées.

<details>
<summary>Solution</summary>

  | sort | uniq -c | sort -rn | head -3

```
